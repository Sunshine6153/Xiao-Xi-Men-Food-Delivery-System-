### 4.2 提交订单与模拟支付接入顺序

现有确认订单页面结构可以保留，数据流改为：

1. 从后端购物车列表计算商品金额。
2. 调用 `POST /user/dish/submit`，至少提交：`addressId`、`remark`、`orderDeliveryTime`、`tablewareAmount`、`deliveryFee`、`orderAmount`。
3. 从提交结果取得 `id` 和 `orderNumber`。
4. 调用 `POST /user/order/payment`，请求体为 `{ "orderNumber": "..." }`。
5. 支付成功以返回的 `orderId`、`status`、`paymentTime` 为准，不再用 `Date.now()` 伪造订单。
6. 跳转真实订单详情页，通过 `GET /user/order/{id}` 加载完整信息。

现有页面中的“配送要求”没有独立后端字段，可按此前决定合并到 `remark`；“帮带费用”对应 `deliveryFee`。

## 6. 当前已确认的业务规则

1. 用户只可取消待支付或已模拟支付但尚未被接取的订单，直接进入已取消，不增加退款状态。
2. 禁止接取自己下的订单；多人同时接取时，只有一个条件更新可以成功。
3. 商户独立接单、出餐；最后一个商户确认出餐后整单才进入待取餐。
4. 配送者只能操作自己接取的订单，依次执行待取餐 → 配送中 → 待确认收餐。
5. 买家确认收餐进入已完成；此前每天零点自动完成已送达未确认订单的规则保持不变。
6. 暂停营业与禁用账号是两个独立状态。

本地数据库已新增 `merchant.business_status`，现有商户默认营业。其他数据库需要执行后端根目录的 `upgrade_merchant_business_status.sql` 一次；已有该字段的数据库不要重复执行。

催单、继续模拟支付和通知均已接入。游客浏览菜单仍暂不调整；真实支付不在当前范围内。

页面从“待接入”改为真实页面时，应同时满足：

- 刷新页面后数据仍存在，不能依赖本地演示数据维持状态。
- 重新登录或换设备后仍能查询到属于当前账号的数据。
- 前端展示的订单状态以数据库返回值为准。
- 商户只能看到包含本商户菜品的订单和金额。
- 用户只能操作自己的订单，配送者只能操作自己接取的配送订单。
- 管理员、商户、用户接口权限不能互相越权。
- 加载中、空数据、请求失败、令牌失效均有明确页面状态。
- 前端不再生成伪订单号、伪订单 ID 或本地模拟支付成功状态。
