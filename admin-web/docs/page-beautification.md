# 小西门小程序页面美化方案

版本：V1.0  
状态：阶段五已完成自验收，待真机视觉验收  
更新时间：2026-09-19

## 1. 美化目标

将当前页面从“通用 AI 生成的餐饮模板感”调整为：

> 简洁、可信、有校园生活气息的真实点餐页面

最终效果不追求装饰丰富，而是让用户一眼看懂：

1. 这里可以买什么；
2. 每份餐品来自哪个摊位；
3. 价格是多少；
4. 如何加入购物车和提交订单；
5. 订单现在处于什么状态。

设计依据是清晰的视觉层级、稳定的对齐和间距、渐进式展示，以及明确的按钮主次。成熟的移动端设计规范也强调：对齐有助于建立信息组织，足够的留白有助于扫描内容，控件应有清晰的层级和足够的触控区域。[Apple Layout Guidelines](https://developer.apple.com/design/human-interface-guidelines/layout) [Apple Buttons Guidelines](https://developer.apple.com/design/human-interface-guidelines/buttons?changes=latest_1__8)

## 2. 当前问题判断

### 2.1 视觉问题

- 圆角、渐变、阴影和浮动卡片使用过多。
- 每个区域都像独立卡片，页面缺少整体菜单感。
- 英文小标题和装饰性文案没有实际业务意义。
- Emoji 和通用图标较多，削弱了品牌识别度。
- 多种蓝色、绿色、橙色同时强调，视觉重点不够集中。
- “推荐”“人气”“校园”等标签偏模板化，缺乏真实内容支撑。

### 2.2 交互和布局问题

- 分类按钮不应表现为一排相互独立的大卡片。
- 详情应该是从底部进入的半屏操作面板，而不是普通弹窗或页面角落内容。
- 主按钮、次按钮和危险操作的视觉等级需要明确。
- 页面必须保留稳定的返回路径和系统安全区域。

## 3. 总体设计原则

### 3.1 菜单优先，不做卡片堆叠

首页应像真实餐饮菜单：

- 白色或浅灰背景；
- 菜品列表优先使用细分割线；
- 只有购物车栏、弹层和重要状态使用卡片；
- 不给每个区域都加阴影和大圆角；
- 菜品图片、名称、价格、加购按钮是核心信息。

### 3.2 只保留一个品牌主色

主色建议为 `#1677FF`，只用于：

- 当前分类；
- 价格；
- 加购按钮；
- 主操作按钮；
- 关键状态。

其他颜色仅用于语义状态，不做装饰：

- 成功：`#21B573`
- 警告：`#E99A3D`
- 错误/取消：`#D96C63`
- 普通文字：`#202B36`
- 辅助文字：`#8A96A3`
- 分割线：`#E9EDF1`

禁止使用大面积渐变作为页面背景或卡片背景。

### 3.3 文字直接说明功能

删除无实际作用的英文和装饰文案：

- `YOUR SELECTION`
- `READY TO ORDER`
- `ORDER CENTER`
- 泛化的“好吃的人都在选”等宣传语

优先使用直接中文：

- 推荐菜品
- 全部菜品
- 已选 3 件
- 配送到
- 帮带费
- 去确认订单
- 确认支付

### 3.4 分类使用文字导航

分类栏不使用多个独立卡片，采用单行文字导航：

```text
全部    炒饭    面食    炸串    饮品
────
```

当前分类使用蓝色文字和底部短线，不使用大图标、渐变背景和厚重圆角。

### 3.5 内容真实化

使用小西门自己的信息替代泛化标签：

- 张记炒饭 · 西门入口右侧
- 现炒，约 15 分钟
- 今天卖出 126 份
- 微辣更香
- 晚上 6 点后排队较多

真实的摊位、位置、口味和制作信息比装饰性标签更能建立可信度。

## 4. 页面级目标

### 4.1 首页

目标：像一张可快速浏览的校园美食菜单。

- 顶部只保留“小西门外卖系统”导航标题。
- 搜索框简洁、低强调。
- 分类为文字导航。
- 菜品采用紧凑列表和细分割线。
- 菜品图片统一比例，避免每张图大小不同。
- 价格和加购按钮突出，其他内容降级。
- 底部购物车栏使用轻量白色浮层，不使用深色大色块。

### 4.2 菜品详情

使用底部 sheet 展示菜品详情。底部 sheet 适合承载与当前页面紧密相关的选择和确认操作。[Apple Sheets Guidelines](https://developer.apple.com/design/human-interface-guidelines/sheets?changes=_1_1)

- 从底部滑入；
- 白色面板；
- 顶部图片；
- 中部名称、价格、商户和口味；
- 底部只有一个“加入购物车”主按钮；
- 点击遮罩或关闭按钮退出。

### 4.3 购物车

- 按商户分组；
- 使用普通白底列表，不重复堆叠阴影；
- 数量按钮统一大小；
- 金额汇总区域清楚但不夸张；
- “去确认订单”是唯一主操作。

### 4.4 确认订单

- 使用表单分组，不让每一行都成为浮动卡片；
- 地址、配送要求、帮带费和备注按顺序排列；
- 费用计算清楚；
- 页面底部固定一个“确认支付”按钮；
- 登录、支付和错误提示使用明确的系统反馈。

### 4.5 订单和帮带

- 用状态文字和时间轴表达业务过程；
- 避免用大量彩色徽章装饰状态；
- 当前操作只保留一个主按钮；
- 订单列表优先显示地址、状态、帮带费和菜品概要。

### 4.6 我的

- 用户头像和身份信息保持简单；
- 地址管理、订单、帮带记录使用普通列表；
- 退出登录放在用户信息区域下方，作为低强调操作；
- 不使用无意义的统计圆形徽章。

## 5. 分阶段实施计划

当前进度：阶段一至阶段四已完成代码实施，并完成阶段五静态自验收；仍需在微信开发者工具和真机上进行最终视觉验收。

### 阶段一：视觉基础收敛

目标：先消除明显的 AI 模板感。

工作内容：

- 删除无意义英文和装饰性文案；
- 统一品牌蓝、文字色、背景色和分割线；
- 删除大面积渐变；
- 将大圆角统一降低到 6–10px；
- 删除不必要的阴影和浮动卡片；
- 统一页面左右边距和基础间距。

验收标准：

- 页面第一眼能看出是点餐菜单；
- 同一页面只有一个明确的主色；
- 不存在多个抢注意力的装饰性区域；
- 标题和按钮都能直接说明用途。

### 阶段二：首页菜单重构

目标：让首页成为真实可用的点餐菜单。

工作内容：

- 分类改为文字导航和底部选中线；
- 菜品列表改为紧凑列表；
- 统一图片比例；
- 统一菜品名称、商户、描述、价格和加购按钮层级；
- 优化搜索框和上下滚动；
- 重做购物车浮层。

验收标准：

- 用户能快速扫读菜品名称和价格；
- 分类按钮不重叠、不留异常空白；
- 首页可顺畅上下滚动；
- 加购按钮清楚但不喧宾夺主；
- 购物车栏不会遮挡主要菜品内容。

### 阶段三：核心交互视觉统一

目标：让所有操作页面使用同一套交互语言。

工作内容：

- 统一底部 sheet、返回栏和固定底部操作栏；
- 统一主按钮、次按钮、取消按钮和危险按钮；
- 统一数量控制器、输入框、状态标签和时间轴；
- 为所有页面补齐返回路径；
- 为登录、支付、取消、接单等操作补充按压反馈。

验收标准：

- 用户不会因为页面风格变化而迷失；
- 每个页面只有一个最重要的主操作；
- 所有按钮都有明确文字和反馈；
- 弹层、返回和关闭行为符合预期。

### 阶段四：真实内容和细节打磨

目标：让页面摆脱 demo 感，形成“小西门”自己的气质。

工作内容：

- 使用真实菜品图片或统一处理后的本地图片；
- 使用真实商户名称和摊位位置；
- 补充制作时间、口味、排队等有用信息；
- 替换 Emoji 和通用图标为统一图标资源；
- 优化空状态、加载状态、错误状态和暂停营业状态；
- 真机检查安全区、字体、滚动和触控范围。

验收标准：

- 页面内容具有小西门本地特色；
- 没有明显的占位文案或随机装饰；
- 图片、文字和间距在真机上稳定；
- 重要按钮容易点击，状态变化容易理解。

### 阶段五：最终验收

目标：确认视觉、交互和业务流程可以交付给后端联调。

验收流程：

1. 浏览首页并切换全部分类；
2. 搜索菜品并打开详情；
3. 选择口味并加入购物车；
4. 在多商户购物车中修改数量；
5. 选择地址并提交订单；
6. 完成模拟支付；
7. 查看订单状态时间轴；
8. 进入帮带页并完成接单流程；
9. 检查登录、退出和未登录拦截；
10. 检查空状态、错误状态、暂停营业和下架菜品。

## 6. 最终效果定义

完成后，页面应该具备以下感受：

- 第一眼简洁，不被渐变、阴影和装饰吸引；
- 第二眼能快速找到分类、菜品和价格；
- 第三眼能感受到真实校园餐饮，而不是通用模板；
- 所有主要操作都能直接理解；
- 页面之间视觉一致，但不是每个区域都长得一样；
- 蓝色是品牌识别，不是到处铺满的背景色；
- 重要内容靠层级和留白突出，而不是靠更多颜色和圆角突出。

## 7. 设计禁用项

后续开发中默认禁止：

- 无业务意义的英文标题；
- 大面积渐变背景；
- 每个模块都使用圆角卡片；
- 每个按钮都使用高饱和蓝色；
- 使用 Emoji 代替正式图标系统；
- 为了“看起来丰富”增加无实际价值的标签；
- 在同一个页面放置两个以上同等级的主按钮；
- 未经真机验证就继续叠加布局修补规则。
