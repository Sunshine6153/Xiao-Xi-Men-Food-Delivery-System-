# 小西门管理端基础设计（讨论稿）

更新时间：2026-09-22  
状态：基础界面方向已确定；管理员身份采用商户账号角色字段并已完成身份契约联调。未来业务规则仍待解决；本文件主要记录设计，实施进度见分步方案。

## 1. 目标与边界

管理端使用同一套蓝白色视觉体系，为商家与系统管理员提供不同的管理菜单。布局参考苍穹外卖后台常见的「侧栏导航 + 顶栏账户 + 内容工作区」，但不照搬具体页面。第一阶段先确定信息架构和基础交互，再逐项接入后端。

设计原则：

- 功能优先：标题、筛选、表格、操作区按固定顺序排列；常用操作一眼可找。
- 真实内容：没有接口的统计数据不展示虚构数字；未接入功能明确标注状态。
- 克制样式：登录后的管理页面采用白色内容区、深蓝导航、浅灰蓝页面背景；不用渐变、大圆角、装饰性文案或无意义图标。现有登录页作为已确认的例外保持原样。
- 权限清楚：商家只看自身经营数据；系统管理员管理全平台。前端菜单只负责展示，权限必须由后端验证。

## 2. 基础布局

桌面端建议使用固定侧栏、顶部工具栏和可滚动的主内容区：

```text
┌──────────────┬──────────────────────────────────────────────────────┐
│ 小西门管理端 │ 页面位置 / 页面标题                     账号  退出 │
│              ├──────────────────────────────────────────────────────┤
│ 角色对应菜单 │ 页面标题                            页面级主要操作 │
│              │ 筛选条件 / 搜索                                       │
│              │ 数据概览、表格或详情                                  │
│              │ 分页 / 状态反馈                                       │
└──────────────┴──────────────────────────────────────────────────────┘
```

- 侧栏宽约 208–224px；顶部栏高约 56–64px；主内容最大宽度约 1440px。
- 侧栏保留品牌名和当前身份，不放宣传文案。当前菜单用蓝色竖条或浅蓝底标示。
- 页面标题与主操作在同一行。筛选栏只放当前页面真正有用的条件。
- 列表采用白底表格、细分隔线与适度行高；新增、编辑按第 5 节确定的形式打开，避免多层弹窗。
- 桌面和平板提供完整操作。手机收起侧栏，支持查看列表、详情和基础操作；复杂编辑可提示使用较宽屏幕。

## 3. 视觉规范

| 用途 | 建议值 |
| --- | --- |
| 主蓝 | `#1766A6` |
| 深蓝侧栏 | `#123A63` |
| 侧栏当前项 | `#E7F1FA` 或深蓝底上的左侧浅蓝指示条 |
| 页面背景 | `#F4F7FA` |
| 内容底色 | `#FFFFFF` |
| 主文字 | `#20364E` |
| 次要文字 | `#6F8192` |
| 分隔线 | `#E4EAF0` |
| 成功 / 警告 / 错误 | `#2F8A60` / `#C5862F` / `#C4544E` |

- 常规控件圆角 3–5px；内容容器圆角不超过 6px。
- 不使用渐变背景、玻璃效果、厚重阴影、随机插画和 emoji 导航图标。
- 主按钮为纯色蓝；次按钮白底蓝边；危险操作使用文字确认和明确的二次确认。
- 推荐内容字号：页面标题 22–24px，区域标题 16–18px，正文及表格 13–14px。
- 状态同时使用文字和颜色，不只靠颜色区分。

| 订单管理 | 本店订单列表、详情、制作状态 | 管理端接口待开发 |

| 店铺资料 | 查看店铺资料与营业状态；可修改字段待后端确认 | 入口保留，专用接口和权限待明确 |

### 系统管理员

| 一级入口 | 页面重点 | 当前状态 |
| --- | --- | --- |
| 平台概览 | 全平台订单、交易、商户与用户概况 | 聚合接口待开发 |

| 菜品管理 | 下级入口“菜品列表”用于跨商户菜品查询与处理；下级入口“分类管理”用于全局分类新增、编辑、启停和删除 | 分类接口已存在但需补充管理员权限校验；跨商户菜品接口待开发 |

| 数据统计 | 订单量、交易额、用户与商户趋势 | 统计接口待开发 |
| 销量排名 | 菜品/商户销量排行，支持时间筛选 | 排名接口待开发 |

**已确认：**管理员的“数据统计”和“销量排名”保持两个独立入口，不合并为“数据中心”。未开发功能在菜单中保留入口，进入后显示“待接入”、预期用途和当前不可用范围；不得显示可操作的假数据。

**已确认：**商家没有单独的“分类查看”页面或菜单，只在菜品列表中按分类筛选，并在新增、编辑菜品时选择分类。管理员不设置独立的分类一级菜单；“分类管理”放在“菜品管理”下作为二级入口，由管理员维护全局分类。

## 5. 页面模板

### 登录

**已确认：现有登录页保持原样，包括校门照片。**暂不规定商家与管理员登录后分别跳转到哪个页面；不同身份可访问的菜单和操作仍须区分。当前登录接口路径不匹配的问题在正式开发时修正，不属于本轮视觉调整。

### 工作台 / 平台概览

首页具体展示内容暂不定稿，不预先指定两种身份各自必须看到的待办或指标。后续选定指标时，只展示来自真实接口且符合当前身份权限范围的数据；缺少接口的区域显示“待接入”，不填充模拟数字。

### 列表管理

统一结构为「页面标题与新建按钮 → 查询条件 → 结果表格 → 分页」。表格尽量不超过 6–8 个主要字段，复杂信息进入详情。状态操作显示当前状态和操作后的目标状态。删除前二次确认，完成后刷新列表并给出明确反馈。

### 详情 / 编辑

保留返回列表路径。基础信息、图片/口味、状态和更新记录分区呈现。保存按钮位置固定；保存失败时保留输入内容并显示后端错误信息。

**已确认的打开方式：**菜品新增与编辑使用独立页面；商户新增与编辑使用右侧抽屉；分类新增与编辑使用小弹窗。商户抽屉关闭前若有未保存修改，应提醒用户。分类弹窗只承载名称、排序等少量字段。

## 6. 现有后端接口映射

以下基于当前后端源码核对，接口根路径均在 `/admin` 下，鉴权请求头为 `token`。

| 领域 | 现有接口 | 对应页面 |
| --- | --- | --- |
| 登录与退出 | `POST /admin/merchant/login`、`POST /admin/merchant/logout` | 登录、右上角账户菜单 |
| 商户 | `POST /admin/merchant/page`、`GET /admin/merchant/{id}`、`POST /admin/merchant/save`、`POST /admin/merchant/update`、`POST /admin/merchant/status/{status}` | 管理员商户管理；商家自身资料需单独明确接口 |
| 分类 | `GET /admin/category/list`、`GET /admin/category/{id}`、`POST /admin/category`、`PUT /admin/category`、`POST /admin/category/status/{status}`、`DELETE /admin/category/{id}` | 商家菜品筛选与表单分类选项；管理员“菜品管理 → 分类管理” |
| 菜品 | `GET /admin/dish/page`、`GET /admin/dish/{id}`、`POST /admin/dish`、`PUT /admin/dish`、`POST /admin/dish/status/{status}`、`DELETE /admin/dish/{id}`、`POST /admin/dish/upload` | 菜品管理 |

前端登录已接入 `POST /admin/merchant/login`，成功码为 `200`；登录和刷新后的身份通过 `GET /admin/auth/me` 核验。

## 7. 后端配合项与权限风险

1. **已解决身份契约：**商户账号使用 `role = ADMIN / MERCHANT`；登录响应和 JWT 带角色，`GET /admin/auth/me` 返回服务端核验后的身份。当前 `admin` 测试账号为 `ADMIN`，`testmerchant` 为 `MERCHANT`。
2. 业务接口的服务端权限边界仍需按实施步骤 7 完整验收。管理员菜单不能只靠前端隐藏控制。
3. **已确认：全局分类由系统管理员维护。**商家只通过菜品筛选和菜品表单使用分类，不设置分类页面；后端需限制分类写接口，不能仅靠前端隐藏操作按钮。
4. 当前菜品接口根据 JWT 中的商户 ID 限定范围。管理员“菜品管理 → 菜品列表”需要独立的全平台查询和操作权限，不能复用商家的本店视图来假装实现。
5. 管理端订单、用户、统计、销量排名接口尚未就绪。字段、时间范围、分页和权限范围应在页面实现前确定。

### 8.1 已确认

| 事项 | 决定 |
| --- | --- |
| 分类权限和位置 | 商家在菜品筛选和表单中使用分类，无单独页面；管理员通过“菜品管理 → 分类管理”维护全局分类 |

| 登录后落点 | 现阶段不按身份指定不同跳转页，也不预定首屏指标 |
| 登录页 | 保留现有校门照片及页面样式，不做本轮视觉改造 |
| 适配范围 | 桌面和平板完整操作；手机支持查看与基础操作 |
